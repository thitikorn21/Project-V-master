# Classification (ระดับชั้นข้อมูล — ตารางเริ่มต้นแบบสมมติ)

ทุกโน้ตต้องมี `classification` (SPEC §5.1) ระดับที่ repo นี้รับได้กำหนดใน [profile.yml](profile.yml) และตรวจโดย CI (classification-guard)

| ระดับ | ความหมาย | ตัวอย่าง | ส่งเข้าโมเดล/ผู้ให้บริการแบบไหนได้ |
|---|---|---|---|
| `public` | เปิดเผยได้ | ตัวอย่างสมมติใน master, เอกสารสาธารณะ | ทุกแบบ |
| `internal` | ใช้ภายในองค์กร | นิยาม field, กฎธุรกิจทั่วไป | เฉพาะบริการที่มีสัญญา/นโยบายว่าไม่นำข้อมูลไปเทรน และองค์กรอนุมัติแล้ว |
| `confidential` | รั่วแล้วเสียหาย | ยอดขายจริง, ข้อมูลลูกค้าแบบรวม | เฉพาะบริการที่องค์กรอนุมัติเป็นรายตัว และเปิดใช้ข้อตกลงด้านข้อมูลแล้ว |
| `restricted` | ห้ามออกนอกระบบ | ข้อมูลส่วนบุคคลรายคน, credential | **ห้ามส่งเข้าโมเดลภายนอก** |

กฎ:
- Conductor ต้องไม่ส่ง context ที่ระดับสูงกว่าที่ executor นั้นรับได้ (SPEC §9.4)
- ต้องตรวจนโยบายการเก็บข้อมูลและการนำไปเทรนของผู้ให้บริการแต่ละรายเป็นระยะ และบันทึกผลใน `governance/local/`
- **master repo รับได้แค่ `public`**
